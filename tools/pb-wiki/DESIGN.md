# Требования к дизайну — Phantom Brigade DB

> **Принятые решения (v2):** основной режим — **гибрид: таблица по умолчанию** +
> переключатель на карточки. Стиль — **чистый дата-интерфейс с лёгкими акцентами
> PB** (цвета редкости, иконки, шрифт-акцент в заголовках). В переработку идёт
> **всё**: сортируемая таблица, диапазонные фильтры + чипы + счётчики,
> сравнение-таблица, URL-состояние + hover-tooltip.


Документ фиксирует, каким должен быть интерфейс базы снаряжения, чтобы им было
удобно пользоваться. Основано на разборе эталонных игровых баз (light.gg,
Wowhead, maxroll.gg) и best practices фасетного поиска (Baymard, Nielsen Norman
Group).

---

## 0. Диагноз: что плохо в текущей версии

| Проблема | Почему это больно |
|---|---|
| Только «стена карточек» | Карточки одинаковые, глазу не за что зацепиться; низкая плотность → бесконечный скролл |
| Нельзя сравнить много предметов разом | Нет таблицы с сортируемыми колонками — а это главный сценарий «какая пушка бьёт сильнее» |
| Фильтры примитивные | Только теги-чипы. Нет диапазонов (урон/масса/дальность от–до), нет счётчиков, нет сброса по одному |
| Состояние теряется | Нет URL-состояния — нельзя расшарить выборку или вернуться назад |
| Детальная панель перекрывает список | Выезжает поверх, нельзя смотреть деталь и список одновременно |
| Слабая визуализация статов | Пары «ключ-значение» без баров, без сравнения с «типичным», без цветовых акцентов |
| Нет мелочей UX | Нет tooltip при наведении, горячих клавиш, внятных пустых состояний |

## 1. Информационная архитектура

- **Единая таблица-первого-класса** — основной режим. Строка = предмет,
  колонки = ключевые статы. Как в light.gg DB и списках Wowhead.
- **Секции по типу слота** доступны как быстрый переход, но не как отдельные
  страницы: торс / ноги / рука / осн. оружие / доп. оружие / ранец /
  модификации.
- **Три уровня детализации**: строка таблицы → hover-tooltip (быстрый взгляд) →
  полная карточка предмета (по клику).

## 2. Раскладка и режимы просмотра

```
┌──────────────────────────────────────────────────────────────┐
│  ЛОГО    [Снаряжение][Модули]      🔍 поиск…        [⊞ карточки][≣ таблица] │
├───────────┬──────────────────────────────────────────────────┤
│ ФИЛЬТРЫ    │  активные чипы: [Осн.оружие ×][Стрела ×] Сбросить │
│ (sticky)   ├──────────────────────────────────────────────────┤
│            │  ▼ Имя      Урон  Дальн  Тепло  Масса  Набор  Мнф │
│ Тип ▸      │  Гидра ML   140    180    130    15    —     ARMS │
│ Набор ▸    │  Коса ML     45    170    140    11    —     ARMS │
│ Вес ▸      │  …сортируемые колонки, зебра, sticky-заголовок     │
│ Категория ▸│                                                    │
│ Диапазоны ▸│                                                    │
│ [сравнить] │                                                    │
└───────────┴──────────────────────────────────────────────────┘
```

- **Переключатель Таблица / Карточки** (по умолчанию — таблица).
- **Master–detail**: деталь открывается в правой панели, но список **не
  перекрывается** (список сужается, а не прячется) — либо отдельная страница
  предмета по прямой ссылке.
- Левая колонка фильтров и заголовок таблицы **прилипающие** (sticky) при
  скролле.

## 3. Поиск

- Мгновенный (по мере ввода, debounce ~120 мс), по имени рус/англ, описанию,
  тегам, ключу.
- **Нечёткий** (опечатки) и по подстроке.
- Подсветка совпадений в результатах.
- Горячая клавиша `/` — фокус в поиск, `Esc` — очистка/закрытие.

## 4. Фильтры (фасетный поиск)

Правила из Baymard / NN/g:

- **Активные фильтры — чипами над таблицей**, у каждого «×», рядом «Сбросить
  всё».
- **Счётчики** у каждого значения фильтра (`Стрела (14)`), пересчитываются
  динамически с учётом уже выбранных фильтров.
- **OR внутри группы, AND между группами** (напр. «набор = Стрела ИЛИ Бейн» И
  «вес = средний»).
- **Диапазонные слайдеры с полями ввода** для числовых статов: урон, дальность,
  тепло, масса. Не бакеты — пользователь сам задаёт «от–до».
- Группы фильтров сворачиваемые; на виду держим 5–6 самых нужных
  (Тип, Набор, Вес, Категория, Производитель), диапазоны — отдельной секцией.
- **Пустое состояние**: «Ничего не найдено» + кнопка «сбросить фильтры».

## 5. Сравнение

- Чекбокс/«+» на строке и в карточке → плавающая панель выбранного (как сейчас,
  но доработать).
- **Таблица сравнения**: статы в строках, предметы в колонках, подсветка
  лучшего/худшего в ряду (с учётом «меньше = лучше» для массы/тепла/разброса).
- Внутри сравнения — **тот же ползунок уровня**, чтобы сравнивать на равных
  уровнях.
- Отдельный инструмент, как `light.gg/db/items/compare`.

## 6. Детальный вид предмета

- Открывается справа (master-detail) **и** доступен по прямому URL
  (`#/item/wpn_rifle_sniper_01`) для шаринга.
- **Tooltip при наведении** на строку/карточку — быстрый предпросмотр ключевых
  статов без клика (паттерн Wowhead).
- Блоки: заголовок+иконка → описание → **ползунок уровня + редкость** →
  статы (с барами) → слоты модификаций (цвет по редкости) → состав →
  особенности.
- **Показывать эффект изменения** (уровень/редкость) прямо в статах —
  подсвечивать, что выросло (паттерн maxroll planner).

## 7. Визуализация характеристик

- **Бары рядом с числом**: значение стата нормируется к макс. среди предметов
  того же типа → видно «сильно/слабо» с одного взгляда.
- **Цвет по стату** берём из данных игры (`uiColor` в UnitStats) — урон
  красный, тепло оранжевый и т.д. Единая палитра.
- Иконки статов (уже вытащены) — слева от названия.
- Для брони — честная пометка «доля запаса набора» + бар относительно других
  частей того же слота.
- **Редкость** — единый цветовой код везде: обычное (белый), необычное
  (зелёный), редкое (синий). Из `QualityTables`.

## 8. Состояние и ссылки

- **Всё состояние — в URL** (хэш): выбранная вкладка, фильтры, поиск, сортировка,
  открытый предмет. Работает «назад/вперёд», можно расшарить/сохранить в
  закладки. Критично для оффлайн-файла тоже (работает через `file://`).

## 9. Производительность

- Данных немного (125 + 97), но таблицу рендерить эффективно (пере-рендер только
  при смене фильтра/сортировки). Плавно на слабом железе.
- Иконки — data-URI (уже так), без сетевых запросов.

## 10. Адаптивность

- Десктоп — основной сценарий (трёхколоночный master-detail).
- Узкий экран: фильтры → в выезжающую панель с кнопкой «Показать N», деталь →
  полноэкранная. Таблица горизонтально скроллится в своём контейнере.

## 11. Доступность и мелочи

- Контраст текста ≥ 4.5:1; не полагаться только на цвет (у редкости — ещё и
  подпись/иконка).
- Клавиатура: `/` поиск, `Esc` закрыть, стрелки по таблице, `Enter` открыть.
- Внятные ховер/фокус состояния, курсоры, аккуратные скроллбары.

## 12. Приятные дополнения (по возможности)

- Быстрые пресеты фильтров: «Тяжёлое дальнобойное», «Лёгкое с малым теплом».
- Мини тир-подсказки по DPS-эффективности (урон/тепло, урон/масса) — расчётные
  производные метрики.
- Экспорт текущей выборки в CSV.

## Эталоны (референсы)

- **light.gg** — плотная таблица, 40+ комбинируемых фильтров, отдельный
  compare-инструмент.
- **Wowhead** — сортируемые таблицы + богатые hover-tooltip.
- **maxroll.gg** — planner с наглядным эффектом изменений, тир-листы.
- **Baymard / NN/g** — чипы активных фильтров, диапазонные слайдеры, счётчики,
  OR/AND-логика, 5–6 фасетов на виду.
