# Steam co-op — совместные игры

Статичные страницы со списком игр для совместной игры: split-screen и общий экран
на одном устройстве, а также онлайн- и LAN-кооп. Режимы переключаются галками.

Две страницы на одном движке:

| страница | что показывает | размер бандла |
|----------|----------------|----------------|
| `index.html` → `dist/steam-coop.html` | что **есть** на двух аккаунтах — 671 игра | 305 КБ |
| `store.html` → `dist/steam-coop-store.html` | что **можно купить** — 5 779 игр | 2,5 МБ |

Файлы:

- `fetch.py` — свои игры → `data.js`
- `fetch_store.py` — магазин минус владение → `store_data.js`
- `page.css`, `page.js` — общие стили и логика обеих страниц
- `index.html`, `store.html` — оболочки: свой набор колонок и фильтров
- `hidden.js`, `hidden_store.js` — списки скрытых игр, коммитятся, едут вместе с бандлами
- `build.py` — склеивает всё в самодостаточные файлы в `dist/`
- `cache.json`, `cache_store.json`, `store_ids.json`, `dist/` — кеши и сборки, в гит не идут

Колонки берутся из `thead data-k` конкретной оболочки, поэтому шаблон строки один
на две страницы: у своих игр есть «Учётная запись» и «Наиграно», у магазина — «Цена».

## Переносимый файл для телефона

```sh
python3 tools/steam-coop/build.py      # -> dist/steam-coop.html и dist/steam-coop-store.html
```

Скрипт печатает фактические размеры — они и есть источник истины.

Один файл без внешних зависимостей: данные вшиты в `<script>`, CSS и JS внутри, ни одного
запроса в сеть при открытии. Кидайте куда угодно — Telegram себе, AirDrop, почта, облако,
`adb push`. Открывается любым мобильным браузером, интернет нужен только чтобы перейти
по ссылке на игру.

Данные не перекачиваются: `build.py` берёт готовый `data.js`. Порядок при обновлении —
сначала `fetch.py`, потом `build.py`.

На узком экране (≤700 px) вёрстка переключается сама:

- таблица становится карточками — горизонтальной прокрутки нет;
- панель фильтров свёрнута, первым виден список;
- ссылки по умолчанию ведут в веб-магазин, а не в `steam://` (мобильное приложение Steam
  обычно перехватывает `https`-ссылки само, а `steam://` с `file://`-страницы может никуда
  не привести). Переключатель в шапке остаётся — можно проверить оба варианта на девайсе;
- кнопка `▶ запуск` скрыта: с телефона игру всё равно не запустить.

## Обновление данных

```sh
STEAM_API_KEY=<ключ> python3 tools/steam-coop/fetch.py
```

Ключ берётся на <https://steamcommunity.com/dev/apikey> (домен можно указать `localhost`).
В файлы он не попадает — только переменная окружения. Флаг `--refresh` сбрасывает кеш
и перекачивает данные магазина заново; без него повторный запуск дёргает Steam
только для новых игр.

Полный прогон — 2 запроса на библиотеки + 16 пачек по 200 appid, около минуты.
Это только своя библиотека; магазин обновляется отдельно, см. ниже.

## Страница магазина (`store.html`)

```sh
STEAM_API_KEY=<ключ> python3 tools/steam-coop/fetch_store.py --min-reviews 100
python3 tools/steam-coop/build.py
```

Перебирает выдачу поиска магазина по категориям **39, 24, 37, 38, 48**, вычитает всё, что есть
на аккаунтах, и обогащает остаток. Все пять категорий нужны: ни одна не надмножество другой —
например Jackbox Party Pack 3, UNO и CoD WWII имеют 39 без 24. Прогон на 26.07.2026:

| шаг | число |
|-----|-------|
| собрано appid из поиска (5 категорий) | 44 193 |
| минус владение (3 022) | 41 171 кандидат |
| прошли предикат «есть режим совместной игры» | 21 120 |
| попали в файл при пороге 100 отзывов | 5 779 |

Разбивка файла по режимам (суммы пересекаются — одна игра бывает и локальной, и онлайновой):
39 — 1 439, 24 — 1 586, 37 — 1 388, 38 — 3 845, 48 — 548.

Порог по отзывам обязателен: без него файл 8 МБ и 21 тысяча строк, которые телефон не отрисует.
Гистограмма печатается при каждом прогоне, порог задаётся `--min-reviews`; при 100 файл 2,5 МБ.
Ещё не вышедшие игры **исключены из порога** — у них отзывов нет по определению, иначе фильтр
«показать ещё не вышедшие» (1 413 игр) оказался бы пустым.

Перебор занимает ~35 минут: 440 страниц поиска с паузой 1,5 с (поиск магазина щедро отдаёт 429)
плюс 105 пачек обогащения. Кешируется в `store_ids.json` и `cache_store.json`, повторный
прогон с другим порогом — мгновенный.

Дополнительно к общим фильтрам: **цена** (ползунок порога + «только бесплатные»),
**«показать ещё не вышедшие»** (по умолчанию скрыты — для списка покупок это шум).
Колонки «Наиграно» и «Учётная запись» отсутствуют, кнопки `▶ запуск` нет.

Список рисуется по 400 строк с кнопкой «Показаны первые 400 из N — показать все», поиск
с задержкой 150 мс: без этого перерисовка двух тысяч строк на каждый символ подвешивает телефон.

### Чего там заведомо нет

- **Делистнутых игр.** Источник — поиск магазина, а снятое с продажи в нём не появляется.
  Проверка на наших данных: из 210 своих co-op игр в выдаче нашлось 205 (97,6 %); пятеро
  непопавших — Laser League, NBA Playgrounds, WWE 2K Battlegrounds и подобные, которые
  и купить нельзя.
- **Игр с меньше чем 100 отзывами** — 15 341 штука отброшена, число выведено в подвале страницы.
  Невышедших это не касается, для них порога нет.
- Цены — снимок на момент сборки, регион US.

## Режимы совместной игры — переключатели

В файлы попадает всё, что вообще про совместную игру; какие режимы показывать, решают
галки в блоке «Режим совместной игры». Игра проходит, если включён **хотя бы один** её режим.

| галка | категория Steam | предикат | по умолчанию |
|-------|-----------------|----------|--------------|
| Split-screen co-op | 39 Shared/Split Screen Co-op | `39` | вкл |
| Общий экран | 24 Shared/Split Screen | `24 && (9 \|\| !37)` | вкл |
| Split-screen PvP | 37 Shared/Split Screen PvP | `37` | выкл |
| Онлайн-кооп | 38 Online Co-op | `38` | выкл |
| LAN-кооп | 48 LAN Co-op | `48` | выкл |

Первые три — на одном устройстве, общий экран. Онлайн и LAN требуют двух устройств.
Remote Play Together (44) в файлы не попадает вообще.

Предикат категории 24 не голый, и это важно: Steam вешает 24 и на файтинги, где «общий экран»
означает мордобой, а не кооп. Условие `9 || !37` пускает игры с пометкой Co-op и игры вообще
без пометки режима (hotseat, старые аркады), но отсекает те, что помечены только как PvP —
для них есть своя галка. Без этого уточнения в кооп-список лез бы Mortal Kombat.

Метки в строке показывают все режимы игры сразу, поэтому видно, чем именно она подходит:
Stardew Valley — `split-screen co-op` + `общий экран` + `онлайн-кооп` + `LAN-кооп`,
Terraria — только `онлайн-кооп`.

Добавить режим — одна строка в массиве `MODES` в `page.js`: галка, счётчик, метка в строке
и фильтрация появятся сами. Если правите список категорий, не забудьте расширить и сборщики —
в файл попадает только то, что они пропустили.

Своя библиотека на прогоне 26.07.2026: 671 игра про совместную игру — 179 с явной 39,
242 проходят по «общему экрану» (в дефолте вместе это 264), 413 с онлайн-коопом, 77 с LAN.
Группа «общий экран» размытее: там попадается hotseat (ход по очереди, напр. Age of Wonders III),
а не одновременная игра — метки в строке позволяют отличить.

## Открытие в клиенте Steam

Переключатель в шапке — **Steam-клиент / Браузер**:

| ссылка | куда ведёт |
|--------|-----------|
| название игры, режим «Steam-клиент» | `steam://store/<appid>` — страница магазина внутри клиента |
| название игры, режим «Браузер» | `https://store.steampowered.com/...` в новой вкладке |
| `▶ запуск` (только свои игры) | `steam://run/<appid>` — сразу запускает игру |

Выбор режима запоминается в `localStorage`. По умолчанию — клиент.

При первом клике браузер спросит разрешение открыть Steam («Открыть Steam?») — можно
поставить галочку «всегда разрешать для этого сайта». Если страница открыта через `file://`
и браузер режет `localStorage`, режим просто не запомнится между открытиями, страница работать
не перестанет.

## Скрытие игр

У каждой строки кнопка **`✕ скрыть`** — убирает игру из списка. В сайдбаре, блок «Скрытые»:

- галка **«Показать скрытые»** возвращает их в таблицу притушёнными, кнопка на них меняется
  на `↺ вернуть`;
- **«Вернуть все скрытые (N)»** очищает список целиком, появляется только когда есть что вернуть.

«Сбросить фильтры» снимает галку «Показать скрытые», но сам список скрытых не чистит —
это данные, а не фильтр.

### Список едет вместе с файлом

Базовый список лежит в `hidden.js` (`window.STEAM_COOP_HIDDEN = [appid, …]`) — он попадает
в бандл и одинаков на всех устройствах. Правки на конкретном устройстве хранятся отдельно
в `localStorage` как **diff**, а не как готовый список:

```
показывается скрытой = (файл ∪ скрытые локально) \ возвращённые локально
```

Так сделано потому, что оба простых варианта ломаются: если писать в `localStorage` только
итоговый набор, он навсегда затенит обновлённый `hidden.js`; если не писать вообще — правки
на телефоне некуда девать, страница себя перезаписать не может.

Чтобы правки уехали на другие устройства:

1. кнопка **«Сохранить список в файл»** — браузер скачивает готовый `hidden.js`, и то же
   содержимое показывается в поле рядом (скачивание blob-а со страницы, открытой как
   локальный файл, работает не во всех браузерах, поэтому текст всегда можно скопировать руками);
2. заменить `tools/steam-coop/hidden.js` скачанным;
3. `python3 tools/steam-coop/build.py` — пересобрать бандл.

Локальный diff после экспорта **не чистится**: объединение идемпотентно, так что вреда нет,
а если скачивание молча не сработало — правки не потеряются. Кнопка «Вернуть все скрытые»
глушит и записи из файла (иначе они вернулись бы после перезагрузки).

Если браузер режет `localStorage` для `file://`-страниц, скрытие работает до перезагрузки,
а список из `hidden.js` — всегда.

Сортировки: название, учётная запись, рейтинг Steam, Steam Deck, дата выхода, наиграно.
Фильтры: тип совместной игры, учётная запись (в т.ч. «есть у обоих»), диапазон годов
выхода, категория Steam Deck, минимальный процент положительных отзывов и минимальное
число отзывов.

## Оговорки

- Steam Deck: `3` Verified, `2` Playable, `1` Unsupported, `0` не проверено.
  «Не проверено» в сортировке всегда уходит в конец — это не худшая ступень, а отсутствие данных.
- Рейтинг — доля положительных отзывов на всех языках. Рядом показано число отзывов:
  «95 % на 12 отзывах» и «95 % на 200k» — разные вещи, для этого есть порог по числу отзывов.
- Часть игр (на прогоне 26.07.2026 — 78 из 3022) не отдаёт данные магазина: удалены
  или недоступны в регионе. Их категории неизвестны, в список они не попадают —
  это не значит, что там нет split-screen. Число выводится в подвале страницы.
- Библиотеки читаются через `IPlayerService/GetOwnedGames`: нужен публичный профиль
  с открытыми игровыми данными. Публичные HTML/XML страницы Steam Community для этого
  больше не годятся — они требуют логина даже для открытых профилей.
