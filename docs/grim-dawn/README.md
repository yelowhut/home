# Grim Dawn — парсеры сейвов и БД + разбор билда

Инструменты для чтения сейвов Grim Dawn (`player.gdc`) и базы данных игры (`*.arz`),
плюс сгенерированный справочник компонентов и анализ персонажа.

## Файлы

| Файл | Что это |
|---|---|
| `components.json` | **Справочник 107 компонентов**: для каждого — точные слоты (`slots`) и гарантированные сопротивления (`resists`), из базы игры. Основной артефакт. |
| `tools/gdchar.py` | Ридер `player.gdc`: заголовок, атрибуты, навыки, мастерства, статистика, фракции. |
| `tools/gear2.py` | Экипировка (12 слотов + 2 набора оружия) с аффиксами, аугментами, компонентами. |
| `tools/bags.py` | Инвентарь (сумки) и персональный стеш. |
| `tools/arz.py` | Ридер формата `.arz` (LZ4-сжатая БД записей игры). |
| `tools/build_components.py` | Строит `components.json` из `database.arz` + аддонов. |
| `tools/final_map.py` | Печатает карту «компонент → слот» для набора компонентов. |

## Запуск

Требуется Python 3 + пакет `lz4` (`pip install lz4`).

Пути задаются переменными окружения (значения по умолчанию — под текущую машину):

```bash
export GD_DIR="C:/games/Steam/steamapps/common/Grim Dawn"          # установка игры
export GD_SAVE_MAIN="C:/games/Steam/userdata/337375846/219990/remote/save/main"
export GD_SAVE_FILE="$GD_SAVE_MAIN/_yelowhut/player.gdc"            # конкретный персонаж

cd tools
python gdchar.py            # сводка по персонажам
python gear2.py             # экипировка
python bags.py              # инвентарь и стеш
python build_components.py  # пересобрать ../components.json из БД игры
```

## Формат `player.gdc` (реверс, ключевые нюансы)

- **Шифрование:** первый uint32 = seed `^ 0x55555555`. Таблица из 256 ключей строится
  `k = rotr(k,1); k = (k * 39916801) & 0xFFFFFFFF`. Чтение: `val ^= key`, затем
  `key ^= table[raw_byte]` для каждого сырого байта (int XOR-ится целиком по key,
  но key продвигается побайтно — поток ключа не зависит от группировки чтений).
- **Заголовок:** magic `0x58434447` («GDCX»), version, имя(utf-16), пол, класс,
  уровень, hardcore, `expansion` байт, **header-checksum (4 байта raw, не двигают key)**,
  `data-version`, 16-байтное mystery-поле, затем блоки.
- **Блок:** `id`(int) + `length`(**raw, БЕЗ обновления key**) + контент + `checksum`(4 байта).
  Checksum на диске == текущему значению key → **им можно ресинхронизировать ключ**
  после пропуска контента блока по длине. Это делает парсер устойчивым.
- **Версионные ловушки (иначе рассинхрон):**
  - Block8 (навыки) **v8**: у записи `CharacterSkill` +1 байт после `transition` (нет в v5).
  - Item (экипировка/инвентарь) **v11** (трансмог из GD 1.2): +4 int-поля в хвосте предмета.

## Формат `.arz` (БД игры)

Заголовок (24 б) → таблица строк → таблица заголовков записей → тело (LZ4-block, размер известен).
Запись = поток полей: `type`(int16: 1=float,2=строка-индекс,иначе int) + `count`(int16) +
`fieldname`(int32-индекс) + значения. Компоненты — записи `records/items/materia/comp*.dbr`
с `Class=ItemRelic`; совместимость слотов — булевы флаги (`head=1`, `shield=1`, `ring=1`…),
человекочитаемо в `FileDescription`.

## Разбор персонажа `_yelowhut` (ур. 49, Commando: Soldier 50 / Demolitionist 20)

**Проблемы:** умирает / мало урона.
- **Смерти** — не докачаны сопротивления: голые аэтер/хаос/пирс/витализ/кровотечение,
  на старте 0 аугментов и почти нет компонентов при полном стеше компонентов.
- **Урон** — билд размазан: ~28 очков в огненный Vindictive Flame при физическом Blade Arc
  (огонь не масштабирует физ.атаку). Хитрость 290 в ущерб Физике.

**План (без крафта/репутаций):**
1. Разложить компоненты по пустым слотам (сверяясь с `components.json`) — упор на дыры в резистах.
2. Позже: реликвия (крафт), фракц.аугменты на пирс.
3. Респек: убрать огненные узлы, добить выживание Soldier (Menhir's Bulwark и т.п.).
4. Атрибуты дальше — только Физика. Играть через набор со щитом при проблемах с выживанием.

## Важные исправления (память ≠ данные игры)

Проверка по `components.json` вскрыла ошибки «по памяти»:
Frozen Heart → **только Кольца**; Chains of Oleron → **только Торс**;
Mark of the Myrmidon → **только Щит**; Runestone → **только Голова** (аэтер+стихии+яд);
Spellwoven Threads / Unholy Inscription / Consecrated Wrappings → **только Руки**.
Вывод: по слотам компонентов всегда сверяться с `components.json`, а не с памятью.
