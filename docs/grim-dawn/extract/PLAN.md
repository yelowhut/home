# План: база знаний Grim Dawn для проектирования билдов

Цель — вытащить из установленной игры полное машиночитаемое описание контента
и механик, чтобы можно было брейнштормить кастомные билды на фактах, а не по памяти.

## Установленные факты о среде (проверено, не гадание)

- Игра: `C:/games/Steam/steamapps/common/Grim Dawn`, все 4 базы на месте:
  `database/database.arz` + `gdx1`/`gdx2`/`gdx3` (Fangs of Asterkarn установлен).
- Слито **82 132** уникальных записи, **341** тип. Порядок перекрытия: gdx3 > gdx2 > gdx1 > base.
- Мастерств **10** (`records/skills/playerclassNN/_classtraining_classNN.dbr`),
  десятое пришло из gdx3.
- EN-тэги: **20 245** (из 4 × `Text_EN.arc`).
- `Levels.arc` содержит один монолитный `world001.map` — формат не реверсен.
- Python 3.13 + `lz4` доступны. `ArchiveTool.exe` из игры распаковывает `.arc`.

## Архитектура

```
docs/grim-dawn/extract/          ← код пайплайна (в git)
  gdlib.py                       ← общее API: ARZ, DB (слияние), Tags, вывод
  00_text.py                     ← .arc → tags_en.json
  01_dump.py                     ← 4 × .arz → gd.sqlite (весь контент одной таблицей)
  10..50_*.py                    ← экстракторы (по одному на предметную область)
  TASKS/                         ← брифы для сабагентов (переиспользуемы в новых сессиях)
  REPORTS/                       ← отчёты экстракторов: схема, счётчики, неуверенности

data/grim-dawn/                  ← данные (вне git, пересобираются за минуты)
  gd.sqlite  (910 MB)            ← сырьё: 82132 записи
  tags_en.json (1.7 MB)
  items.jsonl, skills.json, devotions.json, ...   ← продукт
```

Ключевое решение: **сначала полный дамп в SQLite, потом все экстракторы работают SQL-ом**.
Никто не парсит `.arz` повторно — это делает задачи независимыми, дешёвыми и параллельными.

## Этапы

### Этап 0 — фундамент ✅ (сделан вручную, не делегировался)
Качество фундамента определяет качество всего остального, поэтому он написан сразу набело:
`gdlib.py`, `00_text.py`, `01_dump.py`. Сборка `gd.sqlite` — 17 секунд.

### Этап 1 — экстракторы (8 параллельных сабагентов на Sonnet)

| # | Задание | Выход | Риск |
|---|---|---|---|
| 10 | Предметы: оружие/броня/украшения/сеты | `items.jsonl` | низкий |
| 11 | Аффиксы и правила роллов | `affixes.jsonl` | средний (связь таблица→слот) |
| 20 | 10 мастерств, деревья навыков, скейлинг по уровням | `skills.json` | низкий |
| 21 | Созвездия, аффинити, небесные силы | `devotions.json` | средний |
| 30 | Лут-таблицы, дроп, MI, монстры-источники | `drop_sources.jsonl` | средний (веса ≠ шансы) |
| 31 | СПАЙК: география мира | `regions.json` | **высокий, результат не гарантирован** |
| 40 | Компоненты, аугменты, рецепты, фракции | `components.json`, `augments.jsonl` | низкий |
| 50 | Константы, формулы, типы урона, кэпы | `mechanics.json` | средний (часть формул в Game.dll) |

Задание 31 намеренно ограничено по усилиям: честный отчёт о нереверсенном формате
считается успехом, выдуманные координаты — провалом.

### Этап 2 — сшивка (после этапа 1)
- `90_query.py` — CLI поиска по всем выходам (поиск предмета/навыка/дропа одной командой).
- `KB.md` — карта данных: что где лежит и на какие вопросы отвечает.
- Кросс-валидация: сверить выходы разных заданий между собой (например, гранты скиллов
  из задания 10 должны резолвиться в навыки из задания 20).

### Этап 3 — применение
Брейншторм билдов поверх собранных данных, с проверкой каждого утверждения по файлам.

## Правила, общие для всех заданий

Вынесены в `TASKS/_COMMON.md`. Суть: не выдумывать семантику полей, хранить ссылку на
запись-первоисточник, выкидывать нулевые поля, обязательный раздел «в чём не уверен»
в отчёте, никаких git-коммитов из сабагентов.

## Воспроизводимость

```bash
cd docs/grim-dawn/extract
python 00_text.py     # тэги
python 01_dump.py     # gd.sqlite (17 c)
python 10_items.py    # и далее любой экстрактор
```
Переменные окружения: `GD_DIR` (установка игры), `GD_DATA` (куда писать).
Данные в git не кладём — пересобираются из игры за минуты, а `gd.sqlite` весит ~1 ГБ.
