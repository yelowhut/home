# База знаний Grim Dawn — карта данных

Что где лежит и на какие вопросы отвечает. Все данные в `D:/git/home/data/grim-dawn/`
(вне git — пересобираются пайплайном из установленной игры за пару минут).

Версия игры: база + все 4 аддона, включая Fangs of Asterkarn (gdx3).
Собрано из 82 132 записей БД игры и 20 245 английских тэгов.

## Быстрый доступ

```bash
cd docs/grim-dawn/extract
python 90_query.py stats                      # что вообще есть
python 90_query.py item --slot ring --stat defensiveChaos --min 15
python 90_query.py drop "Sunherald's Claymore"
python 90_query.py field offensiveFireModifier
python 90_query.py show records/items/....dbr
```
`--json` у любой подкоманды выдаёт машиночитаемый вывод, `--top N` меняет лимит.

## Что известно точно (проверено в данных)

- Максимальный уровень **100**, очков девоушена **55** — `records/creatures/pc/playerlevels.dbr`
- Мастерств **10**, десятое (Berserker) — из gdx3
- Порядок репутации: Nemesis, Hated, Despised, Tolerated, Friendly, Respected, Honored, Revered
- Легендарки и эпики **не роллят случайные аффиксы** — подтверждено на 6308 ссылках
- `ItemRelic` в БД — это **компонент**, а надеваемая реликвия — `ItemArtifact`. Ловушка именования.

## Чего в данных НЕТ (не выдумывать)

- **Базовый кэп сопротивлений 80%** — нигде в `.arz`. Есть только штрафы по сложности
  и повышение кэпа отдельными предметами. Константа в `Game.dll`.
- **Уровень разблокировки навыка по тиру мастерства** — только номер тира; формула в клиенте.
- **Пороги очков репутации** по уровням фракций.
- **Вероятности дропа в процентах** — есть веса и триггеры слотов, но множители сложности
  и формула их свёртки в движке.
- **Квестовые бонусы очков** навыков/атрибутов — в `.qst`, вне охваченной `.arz`-базы.
- Коэффициент OA/DA от Хитрости арифметически не сходится с сырыми статами —
  формула, видимо, работает с нормализованными величинами.

### Формат `drop_sources.jsonl`

Веса лежат **не на верхнем уровне**, а внутри `variants[]` — по одному варианту на слот
дропа: `weight`, `weight_sum`, `chance_hint` (= weight/weight_sum), `path` (цепочка
резолва), `level_bracket`, `difficulty`. На верхнем уровне — `slot_trigger_pct`
(шанс, что слот вообще роллится), `monster_level_min/max`, `monster_classification`,
флаги `is_hero`/`is_boss`/`is_superboss`/`is_nemesis` и `variant_count`.

`chance_hint` — это доля веса внутри одной таблицы, **не итоговый шанс дропа**, и посчитан
он только для 11% вариантов. Свёрнутая по всей цепочке вероятность — в `drop_rates.jsonl`.

### Шанс дропа и число убийств

```bash
python 90_query.py kills "Sunherald's Claymore" --best
→ Astros the Sunherald: p=21.2% за убийство, 3 убийства до 50%, 20 до 99%
```
Модель: `P = 1 − Π(1 − шанс_слота × Π(вес/сумма))` по всем звеньям цепочки,
с фильтром по сложности и гейтам уровня. Сложность в данных — это **выбор ветки
лут-таблицы** (`Normal`/`Epic`(=Elite)/`Ultimate`), а не множитель шанса.

Валидировано: гарантированные дропы дают ровно 1.0 (Callagadra → Callagadra's Visage,
834 такие строки), суммы долей по таблицам сходятся 10/10, нарушений монотонности 0.

**Всегда используй `--best`**: у предмета бывает 15+ источников, и сундуки с мизерным
шансом (десятки тысяч открытий) забивают выдачу, скрывая нужного героя.

Допущения, помеченные прямо в строках выхода (`assumptions`):
- `level_gate_summed` (70% строк) — у 79% монстров диапазон уровней в данных `1..250`,
  поэтому неизвестно, какая ветка `LevelTable` сработает; модель суммирует все подходящие,
  **что может завышать шанс**;
- `chest_trigger_assumed_100` (50% строк) — у сундуков нет аналога `chanceToEquip`,
  допущение «сундук всегда генерирует лут» данными не подтверждено.

Не учитывается и в данных не найдено: стат «% Item Rarity», независимость роллов
разных слотов одного монстра, влияние числа игроков, глобальные множители дропа.
Поэтому число убийств — **оценка порядка величины и корректное сравнение источников
между собой**, а не точный прогноз.
