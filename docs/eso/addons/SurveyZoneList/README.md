# SurveyZoneList — форк с четырьмя новыми функциями

Форк аддона **Survey Zone List** (автор @bulton-fr, апстрим —
[bulton-fr/TESO_SurveyZoneList](https://github.com/bulton-fr/TESO_SurveyZoneList)).
Здесь лежит **полная копия** аддона, а не только изменённые файлы: правки затрагивают
почти все файлы, поэтому частичный бэкап после обновления аддона не восстановить.

Версия апстрима, от которой делался форк: **2.0.1**. Версия форка: **2.1.0**.

## Что сделано

Реализованы четыре открытые задачи апстрима.

| Задача | Что было | Что стало |
|---|---|---|
| [#14](https://github.com/bulton-fr/TESO_SurveyZoneList/issues/14) Улучшить определение зоны | Зона вытаскивалась разбором названия предмета, из-за чего появлялись дубли зон | Зона берётся из LibTreasure по id предмета, разбор названия остался запасным вариантом |
| [#12](https://github.com/bulton-fr/TESO_SurveyZoneList/issues/12) Читать исследования в банке | Читался только рюкзак | Опционально читается банк учётной записи, счётчики разделены на рюкзак и банк |
| [#10](https://github.com/bulton-fr/TESO_SurveyZoneList/issues/10) Детализация по зоне | Только общее число исследований | В каждой строке зоны шесть столбцов с иконками ремёсел и количеством |
| [#13](https://github.com/bulton-fr/TESO_SurveyZoneList/issues/13) Проверка очков чемпиона | Нет | Строка предупреждения, если «Обильный урожай» не куплен или не вставлен в слот |

Объём задачи #12 сознательно ограничен банком учётной записи. Апстрим просит ещё
хранилища в домах и банки гильдий, но их содержимое читается только пока открыто
соответствующее окно, то есть потребовался бы кэш в saved variables и его очистка.
Банк учётной записи читается в любой момент, без кэша и без устаревших данных.

## Как устроено

### #14 — определение зоны

Ключ зоны теперь не строка из названия предмета, а id зоны. Цепочка:
id предмета → LibTreasure → mapId → `GetMapInfoById` → zoneIndex → `GetZoneId` →
подъём по `GetParentZoneId` до корневой зоны.

Подъём до корня обязателен. LibTreasure строит индекс по предметам обходом всех карт,
и более поздняя запись затирает раннюю. Поэтому «Alchemist Survey: Stonefalls»
указывает на карту города Эбонхарт, а не на Каменные Водопады. Без подъёма к родителю
это создало бы ровно тот дубль зоны, от которого избавляемся.

Побочный эффект: зоны с римскими цифрами (Крагломор I/II/III, Колдхарбор I/II,
Вротгар I/II/III) схлопываются в одну запись автоматически.

Если LibTreasure не знает предмет (новая глава вышла, библиотека ещё не обновилась),
работает старый разбор названия. Такая зона получает ключ с префиксом `n:` вместо `z:`
и сравнивается с текущей зоной по имени, как раньше. В манифесте зависимость объявлена
как `OptionalDependsOn`, аддон загрузится и без библиотеки.

### #12 — банк

Читаются `BAG_BACKPACK`, `BAG_BANK` и `BAG_SUBSCRIBER_BANK`. Для каждой зоны счётчики
хранятся отдельно по источникам `bag` и `bank`, плюс объединённый `all`.

Каждая сумка регистрируется отдельным обработчиком `EVENT_INVENTORY_SINGLE_SLOT_UPDATE`:
`AddFilterForEvent` объединяет фильтры по И, поэтому один обработчик не может слушать
несколько сумок сразу.

Оповещения и счётчик точек продолжают использовать только рюкзак — исследование из
банка потратить нельзя.

### #10 — разбивка по ремёслам

Ремесло определяется по имени текстуры LibTreasure (`<зона>_survey_<ремесло>`), с
нормализацией двух написаний ювелирного дела. Для зон, распознанных разбором названия,
ремесло ищется по ключевому слову в названии предмета (таблица `craftFindName` в
языковых файлах); это запасной путь, точность там ниже.

Иконки — комплект `master_writ_*`, он полный для всех шести ремёсел.

### #13 — «Обильный урожай»

Звезда ищется по id способности **142220**, а не по названию, поэтому проверка работает
на всех четырёх языках аддона. Проверяется, что очки вложены и что звезда стоит в слоте
панели чемпиона. Обновляется по событиям изменения панели чемпиона.

## Заодно исправлено

Три бага апстрима, которые мешали новым функциям:

- `Alerts:initOpenBagEvent` ставил `inBag = false` в обеих ветках, поэтому `uiOpen()`
  всегда возвращал false и оповещение «последнее исследование здесь» срабатывало при
  простом перекладывании предметов в инвентаре.
- Счётчики зоны менялись инкрементально и накапливали расхождение. Теперь они всегда
  пересчитываются из списка предметов зоны, так что ошибка не переживает ни одного
  обновления слота.
- Список сортировки по умолчанию содержал `nil` в середине (`ORDER_TYPE_TREASURE_NB_TOTAL`
  закомментирован), что молча обрезало таблицу.
- Высота окна считалась на одну строку меньше, чем нужно, и нижняя строка обрезалась.

## Новые настройки

Все новые опции выключены по умолчанию, кроме разбивки по ремёслам.

- **Показывать разбивку по ремёслам** — включено.
- **Ширина текста зоны** — ползунок 150–600, по умолчанию 300. Столбцы ремёсел
  добавляются сверх этой ширины.
- **Читать исследования и в банке** — выключено.
- **Предупреждать, если «Обильный урожай» не вставлен** — выключено.
- **Определять зоны через LibTreasure** — включено, недоступно если библиотеки нет.

Новые плейсхолдеры в формате строки: `<<5>>` `<<6>>` `<<7>>` — банк,
`<<8>>` `<<9>>` `<<10>>` — рюкзак плюс банк. Старые `<<2>>` `<<3>>` `<<4>>` остались
рюкзаком, так что настроенный ранее формат не меняет смысл.

## Что проверить в игре

Две вещи нельзя проверить вне клиента, для них есть отладочные команды:

- `/szl zone` — какую зону аддон считает текущей, доступна ли LibTreasure.
- `/szl zones` — все зоны с источником определения (`zoneId N` или `parsed`) и
  счётчиками. Две строки с одинаковым именем означают, что дубль всё ещё есть.
- `/szl cp` — найденный id звезды «Обильный урожай», вложенные очки, активность.

Стоит проверить, что подъём к корневой зоне нигде не схлопывает лишнего, и что
id способности 142220 всё ещё соответствует «Обильному урожаю» на актуальном патче.
